# Bitácora — 2026-07-18 · SDK de pago (fail-closed) + auto-prueba

## Qué se hizo hoy
Se convirtió BV-SALA de **fail-open (gratis por defecto)** a un producto **de pago, fail-closed**: descargar ⇒ hay que pagar. Sin licencia válida y activa, el pipeline **rechaza** la petición (`LicenseError` en la entrada de `generate()`). La web sigue siendo el único trial gratis.

Decisiones tomadas con el usuario:
- Modelo **de pago obligatorio** (no freemium). Anula la decisión previa de "free tier + graceful degrade".
- API ergonómica `createSavingsLayer({ licenseKey })`.
- **v1 = enforcement offline** (firma Ed25519 + expiración + gracia). Revocación online ("call-home") = follow-up.
- Probar con **CLI** (`pnpm license:demo`) **y** un **botón trial** en el dashboard.
- Licencia legal recomendada para el modelo: propietaria/EULA (se dejó `LICENSE` propietario; se cambió el campo `license` a `SEE LICENSE IN LICENSE`).

## Notas / gotchas
- `tsup` escribe el bundle navegador en `apps/web/vendor/` (sin trackear) pero lo que se **sirve** es `apps/web/public/vendor/bv-sala.js` (commiteado, sin cambios hoy). El demo web funciona con ambos (el servido no tiene enforcement; `app.js` con `devUnlicensed:true` es compatible). Si se quiere que el verificador web use el bundle nuevo, hay que copiar/ajustar `outDir` — pendiente menor.
- `@noble/curves@2.2.0` es devDependency → se **bundlea** en dist (self-contained, `deps:{}`). Import: `@noble/curves/ed25519.js` (con `.js`, `moduleResolution: Bundler`). `dist/index.js` creció a ~139KB por ello.
- El entry gate va **por encima** del `try/catch` de `generate()` a propósito: el catch cae a `failOpenDirect` y se tragaría el `LicenseError` (se re-lanza explícitamente en el catch por si acaso).
- Enforcement offline no cubre revocación (por eso el demo muestra none/válida/expirada/manipulada, no "revocada").
